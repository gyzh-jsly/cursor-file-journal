# 个人数字生命轨迹记录系统

> 一个从0到1独立设计的日记/文件备注工具。记录文字与文件的每一次变迁，让过去的自己“有据可查”。

---

### 📖 项目简介

不满足于增删改查，通过技术手段真实记录文字与文件的每一次变迁。系统由 Spring Boot 驱动，深度融合了业务规则与数据治理思想。

---

### ✨ 核心亮点

**1. 动态时间窗口修改算法**

- **问题**：如何让日记“可改但不篡改”？机械的固定时长无法满足“趁热打铁”的修改需求。
- **方案**：基于创建时间动态计算截止点（上午创建→当天截止，下午创建→24小时后截止）。过期自动冻结。
- **价值**：平衡修改权与历史真实性，解决“23:59创建”等边缘场景的体验问题。

**2. 段评机制（快照+偏移量）**

- **问题**：段评绑定原文，修改后如何保证不丢失、不错位？
- **方案**：存储偏移量+原文片段。修改时弹窗提示，失效时标注“基于旧版本”，并附上旧版原文。
- **价值**：用产品方案替代复杂技术，用户可感知、可校准。

**3. 文件系统原子性监听（过滤临时文件）**

- **问题**：Windows 新建文件时会产生临时状态（如“新建文本文档.txt”），如何避免脏数据？
- **方案**：重新定义业务“新建”，只监听“首次写入内容”（大小从0变>0），忽略空文件。
- **价值**：从底层规避了操作系统临时文件的干扰，用户永远不会看到无意义的临时文件记录。

**4. 完整的“数据生命周期”管理（档案库）**

- **问题**：文件删除后备注也跟着消失，用户反悔或想回顾历史怎么办？
- **方案**：设计“档案库”概念，本地删除仅标记“已删除”并移入封存，保留全部备注。
- **价值**：赋予数据“灵魂”，给用户反悔机会，实现数据从活跃到归档的闭环。

**5. 严谨的批量导入与年历展示**

- **问题**：往期日记导入后，如何避免“污染”主时间线？
- **方案**：导入日记只在归档模块展示，严格隔离，不进入年历。
- **价值**：“当下的记录”与“导入的日记”各归其位，保证系统时间维度的权威性。
