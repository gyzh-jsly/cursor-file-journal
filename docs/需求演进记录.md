# 需求演进记录：从粗略想法到详细设计

## 一、原始需求

### 1.1 主题选择
> “设计一款系统软件，功能类似手机上的笔记app。我喜欢记录，所以更希望记录下第一次的上传日期（最精确，最好描述一下当天天气），记录每一次修改的日期，可以为每一次修改添加备注。总之，我要记录笔记诞生之后的所有状态。”

**关键点：**

- 记录笔记的“完整生命周期”

### 1.2 灵感来源
> “文档显示为系统盘里的一条目录。但是他只显示最后一次修改日期，修改了就会覆盖上一次的日期，而且我想针对这条目录写备注可能有点困难。我想把我的文档存到这个系统软件里，或者进行关联，我要对他每一次修改进行记录和备注。”

**关键点：**
- Windows 文件系统痛点：只有“最后修改时间”，历史被覆盖
- 想给文件写备注，但文件属性不支持
- 想要一个轻量级的版本管理工具（不要 Git/SVN）

---

## 二、需求扩展（讨论中自然生长）

### 2.1 生长节点

**📌 若删除系统监控下的文件**

- 其历史备注何去何从？
- 本地文件还在，下次打开系统，如何保证已删除的文件不被系统检测到？

**📌 若用户删除本地文件呢？/删除目录呢？**

- 系统里的数据何去何从？（衍生出新模块【档案库】）

**📌 若我想管理的文件分散在不同目录下，有必要扫描出目录下所有子文件吗？**

- （衍生出新模块【手选目录】）
  - 可以选监控目录下的文件吗？

**📌 日记要求其具备不可篡改性**

- 很少有人会在写完日记三五天后回头修改，修改功能是否需要？
  - 如果完全不允许修改，写错字怎么办？当时没说清楚怎么办？
  - 修改不节制，不可篡改性又如何体现？多年后回看，你看到的还是“当年真实的你”吗？
- 用户通过文字忆往昔，会有倾诉欲，可设置段评功能。
  - 允许修改，会增加段评工作量。
- 如果用户想要往期的日记也被系统管理呢？是否允许自选日期？（衍生出新模块【过往归档】)

## 三、设计理念的沉淀

### 3.1 定位确认

> “一个以时间权威为核心的日记/记录工具。”

- 只追求一件事：**时间痕迹的真实、完整、可追溯**

### 3.2 核心价值

> “记录笔记诞生之后的所有状态。”

- 不是“存储内容”，而是“存储时间线”
- 每次修改都是一次“痕迹”，不被覆盖

### 3.3 与 Git/SVN 的区别
| 维度     | Git                    | 您的系统               |
| -------- | ---------------------- | ---------------------- |
| 定位     | 团队协作、代码管理     | 个人记录、时间档案     |
| 复杂度   | 高（分支、合并、diff） | 低（只记录时间和备注） |
| 修改次数 | 无限制                 | 有限（3次窗口期）      |
| 可篡改性 | 可改（amend、rebase）  | 过期冻结，不可篡改     |

### 3.4 与 Windows 文件系统的区别
| 维度     | Windows        | 您的系统               |
| -------- | -------------- | ---------------------- |
| 修改历史 | 只保留最后一次 | 记录每一次             |
| 备注     | 不支持         | 支持文件级、修改级备注 |
| 文件监控 | 无             | 支持监控目录、手选文件 |
| 档案管理 | 无             | 档案库封存             |
