# 问题复盘：新建文件出现多余记录 
**需求**：监控目录下创建新文件可以被系统检测到。

**行为**：新建22.txt。结果：系统监测到两条数据，新建文本文档.txt和22.txt。

## 一、问题现象

**出现多余记录**：在Windows文件资源管理器中新建一个文件（如 `22.txt`），系统聚合流页面出现了两个文件记录：`新建文本文档.txt` 和 `22.txt`。

**总结**：Windows 上创建文件时，可能会触发多次事件（`ENTRY_CREATE` + `ENTRY_MODIFY`），或者用户在新建后立即重命名，导致抓到“新建文本文档.txt”这种临时状态。

---

## 二、问题根源

### Windows 新建文件的底层流程

当你新建 `22.txt` 时，事件序列是：

- `ENTRY_CREATE`: `新建文本文档.txt`
- `ENTRY_DELETE`: `新建文本文档.txt`（重命名操作在底层是先删除旧名）
- `ENTRY_CREATE`: `22.txt`

1. 用户右键 → 新建 → 文本文档
2. 系统立即创建一个物理文件，默认名为 `新建文本文档.txt`
3. 系统自动进入重命名编辑状态
4. 用户输入新名称（如 `22.txt`）并回车
5. 系统执行文件重命名操作

---

## 三、根本原因

WatchService 无法区分：

- 用户真正想要的文件（写完了内容、改好了名字）
- 中间状态（新建时临时生成的、正在编辑中的）
